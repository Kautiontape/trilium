# Plan: phone icons at their intended size again

One PR against `ktn` from `ktn-caius-icon-size`. One task, so it runs test-first directly rather than through
subagents.

## Cause

The v0.107.0 upstream sync moved Preact from 10.29.8 to 11.1.1. Preact 11 core's `setStyle` writes `style[key] =
value` with no unit; only `preact/compat` still adds `px` to a number. `Icon` in
`apps/caius-app/src/components/ui.tsx` sets `style={{ width: size, height: size }}` with numbers, so the browser drops
both, and `.icon svg { width: 100%; height: 100% }` grows to the SVG's own size. Every icon in the app goes through
`Icon`: the bottom nav (`App.tsx`), the top bar's `icon-btn`s and the thinking-notes chevron (`Chat.tsx`, `Notes`).

A grep of `apps/caius-app/src` and of the Caius code in `apps/client` (sidebar Plan tab, `services/caius.ts`,
`CaiusNudgeBar`, the Task menu) finds no other numeric inline style: `AreaMeter` passes `pct()` strings and
`TaskRow`'s transform already says `px`.

## T1 · `Icon` writes its size in `px`

**Files.** `apps/caius-app/src/components/ui.tsx` (`Icon`); a new `src/components/ui.spec.tsx`; `src/App.spec.tsx`.

**Tests first.**
- `ui.spec.tsx` (happy-dom): `<Icon name="check" />` renders a span whose `style.width` and `style.height` are exactly
  `"24px"`; `<Icon name="check" size={18} />` gives `"18px"`. Red on the current code (the value is `""` or `"24"`).
- Guard in `App.spec.tsx`: once the app has rendered its shell, every `.icon` in it (the nav glyphs, the add button's
  28px glyph, the mini-chat chevron) has a width and height matching `/^\d+px$/`, and there is at least one.

**Change.** `` style={{ width: `${size}px`, height: `${size}px` }} ``.

**Done.** `cd apps/caius-app && pnpm exec vitest run` green; `pnpm typecheck` green from the repo root.
